# 모바일 열화·QA·언어 검토 — 2026-09-12

기준: GitHub 9b0d858. 업로드된 구버전 Safari 화면에서 지도/대원이 HUD보다 흐리게 보이는 신고를 현재 코드와 대조했습니다.

## 실제 수정

- 터치 또는 높이 520px 미만 화면을 DPR 1로 강제하던 제한을 제거했습니다. 기기 DPR을 최대 3까지 사용하고 출력 캔버스는 400만 픽셀로 제한합니다. 이것은 모든 기기의 FPS 보장이 아닙니다.
- 지도 0.5배 래스터 확대를 제거했습니다. 현재 화면과 128 출력 픽셀 여백만 원래 출력 밀도로 그립니다. 128픽셀 구간 내 이동에서는 캐시를 재사용하며 카메라 배율·지형 파괴·화면 크기가 바뀌면 갱신합니다. 전체 지도를 Retina 배율로 거대하게 할당하지 않습니다.
- 총기 원본은 유지하고 192/384/768px 중 실제 출력 크기에 필요한 중간 이미지를 선택합니다. 코드 총기 외형을 재도입하지 않았습니다.
- CSS 기준 45px 선택 반경을 유지합니다. 해상도 증가가 카메라 확대나 AI 지각을 바꾸지 않습니다.

## 검증 범위

실제 BroadcastCanvas를 로컬 Skia로 렌더링한 16조건, 우리 팀 지속 표시, 무기 PNG 실제 표시, CSS 터치 선택/빈 곳 제외, 동일 캔버스 가로세로 전환·주소창 높이·DPR 변경을 검사했습니다. 고밀도 조건은 360×800/2, 390×844/3, 430×932/3, 412×915/2.625, 844×390/3, 1024×1366/2입니다. 390×844에서는 1170×2532 출력입니다. 태블릿은 픽셀 예산으로 1731×2309입니다. 보고서의 시간은 로컬 Skia 측정치로 변동이 크며 Safari/Chrome 실기기 FPS와 배터리 검증이 아닙니다. 12총기×8방향 검사, 타입 검사 및 빌드도 통과했습니다.

실기기에서 남은 확인: iOS Safari와 Android Chrome 각각 가로세로 전환, 5분 이상 이동/연막 교전, 발열·메모리·프레임, 주소창 확장/축소, 작은 HUD 글자. 전체 기종 무결점으로 판정하지 않습니다.

## C# 전환 판단

현재 확인된 열화 원인은 렌더링 해상도 설정입니다. TypeScript 언어 자체가 이 화질을 강제하지 않습니다. 5v5 시뮬레이션은 이미 Worker에서 실행되고 있습니다. 따라서 이번에는 TypeScript + React + Canvas2D를 유지합니다. 네이티브 앱, 엔진 편집기 또는 프로파일링으로 확인된 CPU 병목 때문에 전환 이득이 생기면 별도로 평가합니다. 이번 작업에서 C# 이식은 하지 않았습니다.

- [MDN devicePixelRatio](https://developer.mozilla.org/en-US/docs/Web/API/Window/devicePixelRatio): Retina Canvas의 출력 픽셀 밀도를 보정하는 방법.
- [Unity 6000.5 브라우저 호환성](https://docs.unity3d.com/6000.5/Documentation/Manual/webgl-browsercompatibility.html): 모바일 브라우저 지원이 있으므로 구버전의 모바일 미지원 문구로 일괄 배제하지 않습니다. 실제 우리 게임의 로딩·메모리·프레임은 이식 프로토타입 측정이 필요합니다.
- [Godot stable C#](https://docs.godotengine.org/en/stable/tutorials/scripting/c_sharp/index.html): C# 프로젝트의 웹 내보내기 제약이 있어 현재 폰 브라우저 중심 배포에 그대로 대체할 수 없습니다.
