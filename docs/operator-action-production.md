# 오퍼레이터 행동·애니메이션 제작 목록

2026-09-11 코드 확인 기준입니다. 이 문서는 제작 계획이며, 목록 작성·원화 생성·시트 연결을 모두 같은 완료 상태로 세지 않습니다. 최신 제작 단위는 **한 시트에 한 동작의 연속 4~6프레임**입니다. 36개 서로 다른 포즈를 한 장에 넣거나 프레임마다 따로 생성하는 방식이 아닙니다.

## 현재 구현과 남은 표현

`src/`는 `artifacts/draft-order-player-generator/src/`를 뜻합니다. 현재 `RealtimeAction`은 14개 이름, `locomotion`은 5개 값입니다. 이것이 완성된 애니메이션 19종이라는 뜻은 아닙니다. `take-cover`는 행동 타입에 있으나 현재 엔진에서 별도 행동으로 대입하는 경로는 확인되지 않았습니다.

| 행동 묶음 | 실제 상태·효과 | 아직 필요한 애니메이션·규칙 |
|---|---|---|
| 정지 조준·대기·방향 전환 | `hold`, `aim`, `facing`, `lookDirection`과 회전 속도 제한이 있습니다. | 정지 조준 루프와 접지된 회전입니다. 이미지를 회전시키는 것과 발을 옮기는 동작은 구분합니다. |

| 목표 장치 | 운반·유실·회수·7초 설치·7초 무력화와 중단 조건이 있습니다. | 회수, 설치, 무력화는 각각의 인체 동작입니다. 현재 회수는 즉시 처리되므로 긴 회수 동작을 붙여 규칙을 임의로 지연하지 않습니다. |
| 다운·구조·사망 | 첫 비헤드 치명상 다운, 기어서 이탈/정지 지혈, 출혈, 4초 정지 소생, 사망과 행동 해제가 있습니다. | 다운 전환·다운 이동·지혈·구조 수행·구조받고 일어나기·사망 전환이 필요합니다. 다운의 부상 이동은 건강한 포복과 무조건 합치지 않습니다. 사망자는 소생시키지 않습니다. |

기본 자산은 12명 정지 원화입니다. 이번 변경에서 COLLIER의 다운 정지 원화를 교체하고 **다운 이동 한 행동의 4프레임**을 두 관전 렌더러에 연결했습니다. 전체 다운·소생·사망 팩이나 전원 팩이 완성된 것은 아닙니다. 새 시퀀스의 원본·좌표·생성 이력은 `art-source/operators/collier/`, 런타임 메타데이터는 `src/operators/collier-downed-crawl-v1.json`에 있습니다.

## AI 임무는 몸동작과 분리합니다

| AI 임무 | 재사용할 몸동작 | 별도로 유지할 판단 |
|---|---|---|
| 수색·소리 확인 | 걷기·저자세 이동·정지 조준 | 실제 시야·소리·마지막 보고 위치, 확인 후 기억 폐기입니다. |
| 복귀·합류·재진입 | 같은 걷기·달리기·정지 조준 | `ScoutOperation`의 작전 국면과 실제 합류 도착 조건입니다. |
| 로밍·우회·측면 접근 | 같은 이동 루프, 필요시 조준 이동 | 로머 순환·경로 선택은 있습니다. 독립적인 완성형 측면 공격 전술은 별도 검증 대상으로 남깁니다. |
| 엄폐 이탈·재배치·수류탄 회피 | 같은 이동 루프 | 관측 위험, 목적지·경로·행동 우선순위입니다. |
| 앵커·교차사격·설치 엄호 | 정지 조준·사격·짧은 이동 | 담당 위치와 사선 분담입니다. ‘엄호’라는 이름의 새 몸동작은 필요하지 않습니다. |

즉, ‘수색 시트·복귀 시트·로밍 시트’를 별도로 생성하지 않습니다. 다만 총을 겨눈 채 옆걸음하는 움직임처럼 실제 신체 동작이 다르면 독립 시퀀스로 제작합니다.

## 제작 순서와 수량

아래 수량은 **한 오퍼레이터·한 주무기 조합**의 계획입니다. 모든 인물·무기·자세 조합을 한 번에 제작하겠다는 약속이 아닙니다.

| 우선순위 | 시트 단위 | 수량·진행 조건 |
|---|---|---|
| 1차: 기본 동작 | 정지 조준 / 걷기 / 달리기 / 앉아 이동 / 사격 복귀 / 해당 주무기 장전 / 다운 전환 / 사망 전환 | **8개 동작 = 8개 시트, 32~48개 연속 프레임**입니다. 이번 다운 이동 시트로 분리·정렬 경로를 먼저 연결했으며, 걷기는 지지발·접지와 루프 품질을 별도로 확인합니다. |
| 2차: 현재 경기에서 필요한 후속 표현 | 자세 전환 4종, 건강한 포복, 조준 이동, 회전, 틀 넘기, 창문 파쇄·통과, 투척, 목표 회수·설치·무력화, 피격, 다운 이동·지혈, 구조 수행·받기 | 각 항목을 독립 시트로 제작합니다. 재사용 검수와 전환 규칙 합의 전에는 총량을 확정하지 않습니다. |
| 3차: 장비별 동작 | 방패 들기·내리기·대기·이동, 카메라 설치·제거, 장약 설치, 고유 가젯 | 그 장비를 실제 사용하는 인물에게만 제작합니다. 공용 인체 움직임은 참고하되 다른 인물의 복장·무기를 복제하지 않습니다. |
| 후속 규칙과 함께 | 드론 조작, 가젯 회수·수동 기폭, 벽 보강·바리케이드, 권총 전환 | 아래 미구현 목록의 상태·조건을 먼저 정한 뒤 제작합니다. |

8시트는 채택할 납품 단위이지 생성 호출·크레딧의 확정 견적이 아닙니다. 재시도 횟수, 소요 시간, 채택 프레임/전체 프레임을 기록해 다음 묶음 크기를 정합니다. 품질이 탈락하면 같은 저품질 시트를 계속 늘리지 않고 실패 원인을 수정합니다. 추가 크레딧 속도 가속 옵션은 사용하지 않습니다.

## 미래 규칙·추가 제안의 경계

- **요청된 후속 범위·현재 미구현:** AUBERT의 이동·원격 관측 드론, 성곽의 벽 보강, 바리케이드 설치·파괴·회수, 주무기↔권총 전환입니다. 드론은 기체 이동·시야·손실과 오퍼레이터의 투입·조작·회수 동작을 구분하셔야 합니다.
- **고유 장비 설정과 구현 차이:** MAGPIE 경첩 절단, 해동 인질 식별 광학, ARBEL 청음 탐침, MARCHAND 감지선, SAVELLI 함정등, BRANDT 고정 사선, HALLORAN 감시선 등은 `Operator.ts`의 설명만으로 실시간 고유 기능이 완성된 것이 아닙니다. 바닥 설치·벽면 부착·광학 조작·기체 투입처럼 손동작이 같은 묶음으로 기획하되 감지·자원·피해·중단 규칙은 장비마다 따로 둡니다.
- **부분 연결:** COLLIER는 작은 발포 소음, MEDVED는 파쇄 경로, REUSS는 방패 판정이 있습니다. 이것이 각 장비 설명 전체의 구현·고증 완료를 뜻하지는 않습니다.
- **추가 제안·승인 및 구현 전:** 린/피킹은 문틈 교전의 가독성을 높일 후보입니다. 실제 몸·총구·피격 영역·노출량과 AI 선택을 먼저 정하셔야 하며, 이미 구현된 엄폐·조준에 붙인 이름으로 처리하지 않습니다. 좌우 동작은 장비 비대칭 때문에 별도 검수합니다.

## 한 동작 시트의 입고 기준

1. **한 인물·한 무기·한 시점·한 동작**의 시작→중간→종료 또는 한 바퀴 루프를 4~6프레임으로 만듭니다. 앉기와 일어서기, 방패 들기와 내리기는 별도 동작입니다. 여러 독립 포즈를 연속 프레임이라고 부르지 않습니다.
2. 새 목표는 **각 프레임의 실제 캐릭터 영역 장축 최소 512px**입니다. 시트 전체 크기나 투명 여백을 포함한 셀 크기로 통과시키지 않습니다. 원본 픽셀에서 측정하며 작은·흐릿한 프레임의 확대 보간으로 기준을 맞추지 않습니다. 프레임 수를 늘려 인물 해상도가 줄면 한 시트 4프레임을 우선합니다.
3. 투명 RGBA, 프레임 밖 여백, 동일 인체·장비 크기, 정확한 탑다운 시점, 손의 파지·총열·탄창·관절과 가림 관계를 확인합니다. 보행은 지지발·골반·이동 거리와 루프 이음새를 함께 봅니다.
4. 물리적으로 다른 무기의 장전은 복제하지 않습니다. 일반 탄창식·불펍/상부 탄창·정밀소총 등은 제작 검토를 묶는 기준일 뿐, 같은 시트를 그대로 쓰는 허가가 아닙니다. 총몸·탄창 위치가 다른 MP5SD·X95·P90 등을 구분합니다. 비대칭 무기·파우치·방패의 무검수 좌우 반전은 금지합니다.
5. 프레임별 영역·pivot·총구를 기록하고 기존 물리 총구와 정렬을 확인합니다. 재생 시간은 경기 시각·속도·정지 상태를 따릅니다. 총구 섬광은 실제 `shot`, 다운·사망은 실제 해당 사건, 구조는 `reviving`과 진행도에만 연결합니다.
6. 투척·회수·카메라 제거처럼 현재 순간 처리되는 행동에 준비 동작이 필요하더라도 미래 사건을 미리 읽어 재생하지 않습니다. 규칙 시간을 바꾸는 작업은 별도로 구현·검증하기 전까지 약속하지 않습니다.
7. 수치 검사와 원본 확대 검수 뒤 실제 크기의 이동·사격·중단·배속·일시정지를 확인합니다. 한 자세를 흔드는 효과, 자동 검사 통과, 정지 스크린샷만으로 연속 동작 완성을 선언하지 않습니다.
