# 오퍼레이터 스프라이트 v2 제작·연결 명세

대상 커밋 `dbe5ffa`. 이 문서는 경기 화면의 캐릭터를 도형 렌더러에서 **통짜 스프라이트**로 되돌리고, 부족한 포즈를 편차 없이 생성하기 위한 지시서입니다.

## 0. 이번에 확정한 결정

이 세 가지는 논의가 끝난 사항입니다. 구현 중 다시 뒤집지 마세요.

1. **무기 교체를 포기합니다.** 캐릭터와 총기를 한 장에 함께 그립니다. 탑뷰 40~60px에서 HK416과 L119A2를 구별할 수 없고, 캐릭터와 별도 생성 총기를 손 위치까지 맞춰 잇는 작업은 생성 모델이 안정적으로 해내지 못합니다. 실루엣이 실제로 다른 경우(저격총·P90·권총·방패)만 별도 시트로 만듭니다.
2. **팔 관절을 그리지 않습니다.** 승인된 걷기 시트를 보면 위팔도 팔꿈치도 보이지 않습니다. 어깨 덩어리 아래에서 전완 두 개가 거의 평행하게 나오고 끝에 손이 총 위에 얹힙니다. 어깨→팔꿈치→손 체인을 그리면 꺾여 보입니다. 런타임에서 팔을 늘이거나 꺾는 방식도 쓰지 않습니다.
3. **한 시트 = 한 행동 = 4프레임 2×2.** 프레임을 한 장씩 따로 생성하는 방식으로 되돌리지 않습니다. 2026-09-11 장전 시도가 이 방식으로 전멸했습니다.

## 1. 지금 상태 (확인 완료)

### 1-1. 만들어 둔 스프라이트를 경기 화면이 쓰지 않고 있습니다

`BroadcastCanvas.tsx` 203행이 `paintMinimalOperator`를 **무조건** 호출하고, 이 함수는 항상 `true`를 반환합니다. 따라서 바로 뒤의 `continue`가 매번 실행되어 스프라이트 경로에 도달하지 않습니다.

## 2. 만들 포즈 (우선순위)

### Tier 1 — 이것만 있으면 전환 가능

| 행동 | 대상 | 비고 |
|---|---|---|
| `idle` (정지 견착) | 12명 | **최우선.** 선수는 대부분의 시간을 정지·각 유지로 보냅니다. 이게 없으면 멈춘 선수가 걷기 프레임에서 다리를 앞으로 뻗은 채 얼어붙습니다 |
| `downed` (다운) | 11명 | COLLIER 제외. 현재 노란 십자 표식으로 대체 중 |

**`idle`을 아끼는 방법**: 걷기 4프레임 중 두 발이 모인 통과 프레임(2·4번)은 정지 자세에 가깝습니다. 우선 이걸 정지용으로 재사용해 전환부터 하고, 전용 `idle` 시트는 그다음에 만들어 교체해도 됩니다. 이 경우 Tier 1은 `downed` 11장뿐입니다. **먼저 이 방법으로 전환해서 화면을 보고, 부족하면 그때 `idle`을 만드는 순서를 권장합니다.**

### Tier 2 — 체감이 크게 오르는 것

| 행동 | 대상 | 비고 |
|---|---|---|
| `sprint` (달리기) | 12명 | 속도 3단계를 넣었으므로 걷기와 달리기가 같은 모션이면 속도 차이가 안 읽힙니다 |
| `death` (사망) | 12명 | 현재 걷기 프레임을 알파 0.4로 깔아두는 것으로 대체 중 |

### Tier 3 — 나중에

`reload`, `vault`(틀 넘기), `objective`(설치·해체), `revive`(구조), `strafe`/`back`(횡이동·후진).

**`reload`는 지금 시도하지 마세요.** 2026-09-11에 3명×2회 전부 탈락했습니다(여분의 손, 사격 손 교체, 탄창을 상부 레일로 삽입). 그때 남긴 결론이 맞습니다 — 무기별 실제 조작 참조와 고정된 총기/손 배치를 먼저 확보한 뒤에 다시 합니다.

### 방패 (별도 트랙)

방패 오퍼레이터는 총이 시트에 박혀 있으므로 **상태별 시트가 따로 필요합니다.**

- `shield-walk` — 방패를 세우고 전진. 보조무기는 몸 옆에 붙어 보이지 않거나 아주 짧게
- `shield-aim` — 방패를 내리고 보조무기 조준. 방패가 몸 왼쪽으로 기울어 머리·다리가 노출된 실루엣

방패를 주는 오퍼레이터 수를 먼저 정하세요. **공격 1명으로 시작할 것을 권장합니다.** 12명 전원에 방패 변형을 만들면 시트가 24장 늘어납니다.

## 4. 생성 규칙 — 편차를 없애는 방법

### 4-1. 레퍼런스 고정

새 행동은 **반드시 해당 오퍼레이터의 승인된 걷기 시트를 이미지 레퍼런스로 물려서** 생성합니다. 텍스트 지시만으로 새로 그리게 하지 마세요. COLLIER 저자세가 무너진 게 이 지점으로 추정됩니다.

레퍼런스로 유지할 것: 총기 형상과 길이, 머리 장비, 복장 색, 손 파지 위치, 인물 크기.
새로 바뀌는 것: 관절 자세뿐.

### 4-2. 배치 단위

**한 행동 12명을 한 번의 배치에서 연속 생성합니다.** 행동을 섞지 마세요. 같은 세션 안에서의 편차가 세션 간 편차보다 작습니다.

### 4-3. 고정 수치

- 인물 장축 원본 512px 이상 (확대 금지)
- 배경 순수 마젠타, 그림자·문자·효과 없음
- 수직 90도 탑다운 정사영, 오른쪽 방향
- **`--world-width`는 그 오퍼레이터의 걷기 배치에서 쓴 값을 그대로 사용** (`walk-batch-20260911.json` 참조: collier 41, arbel 42, aubert 40, medved 46, reuss 46, brandt 51, marchand 40, halloran 51, 성곽 43 등). 행동마다 다른 값을 쓰면 걷다가 멈출 때 몸이 커졌다 작아집니다

### 4-4. 행동별 자세 지시

- **idle**: 두 발을 어깨 너비로, 한 발만 반보 앞. 4프레임은 호흡에 의한 아주 작은 상하 흔들림만. 발 위치는 4프레임 동일
- **downed**: 옆으로 쓰러진 자세. 총은 손에서 떨어져 몸 옆에 놓임. 4프레임은 미세한 움직임만
- **sprint**: 보폭을 걷기보다 크게, 상체를 앞으로. 총은 내려 몸에 붙임(견착 아님)
- **death**: 엎어진 자세. 4프레임 중 1~2에서 쓰러지는 중간, 3~4는 정지

## 5. 앵커 규격

프레임마다 두 점을 기록합니다. 형식은 기존 `<action>-v1-anchors.json`과 동일합니다.

- `pivot` — 헬멧 중심. 유닛의 월드 좌표가 놓이는 점
- `muzzle` — 총구 끝. **사격 이펙트가 여기에 붙습니다**

`downed`·`death`처럼 총을 들지 않은 자세에서도 `muzzle`은 반드시 기록하세요. 값이 없으면 런타임이 `pivot`으로 대체하고 총구 화염이 머리에서 납니다.

## 7. 렌더러 연결

### 7-1. `BroadcastCanvas.tsx` 203행

지금:
```
if(!paintMinimalOperator(...))continue;   // 항상 true → 스프라이트 경로 도달 불가
```

바꿀 것: **스프라이트를 먼저 시도하고, 해당 상태의 시트가 없을 때만 도형 렌더러로 넘깁니다.**

```
// 시트가 있는 상태는 원화로, 없는 상태만 도형 폴백으로 그립니다.
const visual = operatorStateVisual(unit, time);
if (visual && drawOperatorSheet(ctx, visual, unit)) { /* 그려짐 */ }
else paintMinimalOperator(ctx, unit, time, shotAt, asset, reducedMotion, motion);
```

`paintMinimalOperator`를 지우지 마세요. Tier 3 행동(장전·구조·틀 넘기 등)은 당분간 시트가 없으므로 폴백이 계속 필요합니다.

### 7-2. 총기를 두 번 그리지 말 것

시트에는 총이 이미 박혀 있습니다. 스프라이트 경로에서는 **`paintWeaponPart`를 호출하지 않습니다.**

### 7-3. 총구 좌표 출처를 바꿀 것

지금 `muzzlePosition`은 `weaponMuzzleOffset`(무기 길이 기반 계산식)을 씁니다. 스프라이트 경로에서는 **시트 프레임의 `muzzle` 앵커**를 써야 합니다. 시트의 총과 계산식의 총 길이가 다르면 화염이 총열 중간이나 허공에서 납니다.

`TacticalRealtimeSimulation.ts`도 `muzzlePosition`을 임포트합니다. **시뮬레이션 쪽 총구 좌표는 건드리지 마세요** — 명중 판정이 달라지면 이번 작업이 밸런스 변경이 됩니다. 바꾸는 건 렌더링용 좌표 하나뿐입니다.

### 7-4. 도형 렌더러 폴백도 한 가지는 고칠 것

폴백으로 남는 이상 지금의 "총이 몸통을 관통" 문제는 그대로 남습니다. **그리는 순서만 바꾸세요** — 총을 어깨·몸통보다 **먼저** 그리면 개머리판이 어깨 아래로 들어가 관통 느낌이 사라집니다. 팔은 여전히 그리지 않습니다.

## 8. 하지 말 것

- 프레임을 한 장씩 따로 생성 (장전 시트 전멸의 원인)
- 원본 확대 (`upscaled: true`가 되면 탈락)
- 코드로 관절·무기를 다시 그리기
- 런타임에서 팔을 늘이거나 꺾어 총기 접점에 맞추기
- 행동마다 다른 `--world-width` 사용
- 탈락 후보를 런타임 경로(`public/operators/`)에 넣기
- 픽셀 검사 통과를 "행동 팩 완성"으로 집계하기
- 시뮬레이션의 총구 좌표·명중 판정 변경

## 9. 순서와 검증

**1단계 — 연결만 먼저 (생성 없음)**
7-1·7-2·7-3을 적용하고, 걷기 통과 프레임을 정지 자세로 재사용합니다. 다운은 기존 표식 유지. 생성 없이 **기존 24시트가 경기 화면에 나오는 것만** 확인합니다.
검증: `node tests/operator-action-state.cjs`, `node tests/render-broadcast-canvas.cjs`, 그리고 실제 브라우저 관전 1라운드.

여기서 화면을 한 번 보고 판단하세요. 이 단계만으로 충분히 나아졌다면 2단계를 미뤄도 됩니다.

**2단계 — 게이트 먼저, 생성 나중**
6절의 4~9번 검사를 `operator-sprite-audit.cjs`에 추가하고, **기존 24시트를 그 게이트에 통과시켜 봅니다.** COLLIER 저자세가 6번(총열 길이)에서 걸리는지 확인하세요. 안 걸리면 기준값을 조정합니다. 게이트가 이미 아는 불량을 못 잡으면 새 생성물도 못 잡습니다.

**3단계 — Tier 1 생성**
`downed` 11명. 4-1의 레퍼런스 고정, 4-2의 한 배치, 4-3의 고정 수치를 지킵니다. 게이트 통과 후 사람 확대 검수.

**4단계 — 판단 후 진행**
`idle` 전용 시트가 필요한지 화면 보고 결정. 그다음 Tier 2.

방패는 이 4단계가 끝난 뒤에 별도로 시작합니다. 그 전에 `weaponHandling.ts`에 `pistol` family를 추가해야 합니다 — 지금은 권총 7종이 전부 카빈 기본값(5.56×45 / 750RPM / 데미지 32)으로 폴백되어, 방패병이 "권총만 들었는데 HK416 화력"이 됩니다.
