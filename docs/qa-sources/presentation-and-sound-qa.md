# 2부. 연출 추가안 — 싼 것부터

작업량 순으로 정렬했다. 위 3개만 해도 체감이 크게 바뀐다.

## 2-1. 아이들 모션 — 40% 정지 해소 (가장 싸고 효과 큼)

```ts
// 멈춰 있어도 호흡과 좌우 경계는 유지한다. 실제 상태가 없을 때 가짜 동작을 만들지는 않는다.
const idle = !reducedMotion && !moving && !down
  ? Math.sin(time * 1.6 + seedOf(unit.id)) : 0;          // 호흡 ±0.6단위
const scanIdle = unit.action === 'hold' || unit.action === 'aim'
  ? Math.sin(time * 0.5 + seedOf(unit.id)) * 0.09 : 0;    // 시선 좌우 ±5도
```

- `seedOf(unit.id)`로 위상을 어긋나게 해서 다섯 명이 동시에 숨 쉬지 않게 한다
- 몸 방향(`facing`)은 바꾸지 말고 **헬멧 폴리곤만** 좌우로 흔든다. 엔진의 시야 판정은 `facing` 기준이므로 판정에 영향이 없다
- `aim`일 때는 호흡 폭을 절반으로 줄이고 흔들림을 멈춘다 — 조준 중이라는 신호가 된다

이 두 줄이 화면 시간 40%의 인상을 바꾼다.

## 2-2. 사망·다운 연출

경기당 7회 + 5회. 지금은 아무것도 없다.

- **사망**: 0.35초 동안 몸이 진행 반대 방향으로 밀리며 쓰러진 폴리곤으로 전환, 지면에 잔해 표식을 남긴다. 반투명 처리만으로 끝내지 않는다
- **헤드샷 구분**: `hitRegion === 'head'`면 피격 링을 더 짧고 밝게(0.12초, 흰색), 킬피드 항목에 강조. 이미 데이터가 있다
- **다운**: 현재 표식(십자 + 진행 원호)은 유지하고, 몸이 낮아지는 전환 0.25초를 넣는다
- **소생**: 경기당 0.9회뿐이라 희귀한 사건이다. 구조자와 대상을 잇는 선 + 진행 링이면 충분하다

## 2-3. 결정적 순간의 카메라

- **설치·해체 시작**: 0.4초 동안 카메라가 15% 확대. `objective` 사건에 이미 위치가 있다
- **사망**: 0.15초 짧은 흔들림 (수류탄의 1/3 세기)
- **마지막 한 명**: 생존자가 1명이 되면 그 선수로 컷을 고정하고 테두리 색을 바꾼다. `engagements[]`로 상대를 알 수 있다
- **라운드 시작**: 0.8초 전체 지도 → 선두 진입조로 줌인
- **라운드 종료**: 마지막 사건 위치로 컷하고 0.5초 정지 후 패널. 지금은 아무도 없는 스폰을 보고 있다 (이전 QA P2-22)

모두 `reducedMotion`일 때 꺼진다.

## 2-4. 명도 정리

- 정적 지형 `globalAlpha`를 .86 → .62로 낮추고, 캐릭터·가젯은 1.0으로 둔다. 중요한 것만 밝게
- 사이트 A/B 영역에 아주 약한 색조(주황/청색)를 깔아 위치 감각을 만든다
- 진영 색을 캐릭터 외곽선에 적용한다. 2×4단위 점이 아니라 윤곽 전체 (이전 QA P1-06과 같은 수정)
- 피격은 링 하나가 아니라 **몸에 0.2초 플래시**를 준다. 누가 맞았는지가 즉시 보여야 한다

## 2-5. 판단 티커 — 캐릭터에 성격 입히기

`unit.goal`이 경기당 443회 바뀌고 내용이 이미 한글 문장이다.

```
"장거리 사선 불리 · 엄폐 우회"
"열세 판단 후 후퇴·재배치"
"마지막 소리 위치 수색"
"통과 순서 대기 · COLLIER 선행"
```

화면 하단에 `[선수명] 판단 내용` 한 줄 티커를 두고, goal이 바뀔 때만 갱신한다. 선수가 생각하고 있다는 인상이 생기고 새로 만들 데이터가 없다.

단, **선수 위에 띄우지 말 것.** 이전 QA P1-12에서 라벨 4개가 겹치는 문제가 이미 있다. 하단 고정 한 줄이 맞다.

## 2-6. 하지 말 것

# 3부. 사운드 도입안

## 3-1. 이 프로젝트는 사운드를 붙이기 쉬운 구조다

세 가지 조건이 이미 충족돼 있다.

1. **결정론적 사건 로그.** `result.events`의 모든 항목에 `time`(0.1초 단위)과 `position`이 있다. 같은 시드에서 항상 같은 사건이 같은 시각에 나온다 → 오디오를 사건 로그에서 그대로 스케줄할 수 있다
2. **소리 사건이 이미 있다.** 경기당 2,306회. `{ time, actor, message: '총성'|'발소리', position }`
3. **청취 판정이 이미 있다.** `heard(unit, sound, map, now)`가 벽과 거리를 검사한다

새로 설계할 것은 믹싱 규칙과 샘플뿐이다.

## 3-2. 라이브러리는 쓰지 않는다

Web Audio API만으로 충분하다. 필요한 것이 `AudioContext` · `AudioBufferSourceNode` · `GainNode` · `BiquadFilterNode` 네 개다. Howler 같은 래퍼는 이 규모에서 얻는 것이 없다.

## 3-3. 사건 → 소리 매핑

| 사건 | 조건 | 샘플 | 우선순위 |
|---|---|---|---|
| `shot` | 항상 | 무기 family별 (carbine/smg/marksman/bolt) | 1 |
| `impact` `hit=true` | 항상 | 피격 (몸/머리 구분) | 1 |
| `impact` `hit=false` | 항상 | 벽 탄착 | 3 |
| `death` | 항상 | 쓰러짐 | 1 |
| `objective` `planted`/`defused` | 항상 | 장치 가동음 / 해체 완료 | 1 |
| `utility` `grenade-exploded` | 항상 | 폭발 | 1 |
| `utility` `wall-breached` | 항상 | 파쇄 | 1 |
| `utility` `smoke-thrown` | 항상 | 연막 분사 | 2 |
| `utility` `window-broken` | 항상 | 유리 | 2 |
| `action` `traversal:*` | 항상 | 창틀/포복 | 3 |
| `reload` | 항상 | 장전 | 2 |
| `downed` / `revive` | 항상 | 신음 / 지혈 | 2 |
| `sound` `발소리` | **감쇠·병합 필수** | 발소리 | 4 |
| 라운드 시작·종료 | — | UI 스팅어 | 0 |

## 3-4. 함정 세 개

### (1) `heard()`를 그대로 쓰면 거의 무음이 된다

```ts
return now - sound.at < 2.5 && distance(...) < 260 * sound.loudness * wallLoss;
```

260단위 = **6.5m**다. 총성이 6.5m, 벽 뒤면 2.3m, COLLIER 소음기는 2.5m. 이건 **AI의 청취 판정**이고 그 목적에는 맞지만, 중계 오디오에 그대로 쓰면 카메라 밖 총격전이 들리지 않는다.

중계용은 별도 반경을 쓴다. 권장: **화면에 보이는 범위 + 여유 40%**를 0dB, 그 밖은 거리 제곱 감쇠, 벽 뒤는 lowpass 600Hz. 카메라 위치 기준이고 선수 위치 기준이 아니다.

### (2) 발소리 2,306회를 그대로 재생하면 소음이다

초당 28회다. 세 단계로 줄인다.

```
1. 같은 틱의 발소리를 위치로 묶는다 (반경 60단위 내 → 1회)
2. 카메라 시야 밖은 버린다
3. 발소리 채널 동시 발음 3개 제한, 오래된 것부터 정지
```

거기에 같은 유닛의 발소리는 최소 간격 0.28초를 강제한다. 걷기 10Hz sin 애니와 맞춰 두 걸음에 한 번만 낸다.

### (3) 4배속에서는 소리를 줄여야 한다

`playbackRate`를 올리면 총성이 찍찍거린다. 배속별로 재생 대상을 바꾼다.

| 배속 | 재생 |
|---|---|
| 1× | 전부 |
| 2× | 우선순위 1~2, 발소리 끔 |
| 4× | 우선순위 0~1만 (총성·사망·목표·폭발) |

피치는 건드리지 않는다. 사건 수를 줄이는 쪽이 항상 낫다.

## 3-5. 모바일 자동재생

브라우저는 사용자 제스처 없이 `AudioContext`를 시작하지 못한다. **`편성 확정 · 출전 →` 버튼이 unlock 지점이다.** 그 클릭 핸들러에서 `context.resume()`을 호출하고 샘플 로딩을 시작한다. 경기 화면 진입까지 2초 정도 여유가 있어 로딩 시간이 가려진다.

```ts
// 출전 버튼 핸들러에서 한 번만 호출한다. 사용자 제스처 없이는 오디오가 시작되지 않는다.
async function unlockAudio(): Promise<void> {
  if (!context) context = new AudioContext();
  if (context.state === 'suspended') await context.resume();
  void loadSamples();   // 병렬 로딩, 실패해도 경기는 진행한다
}
```

음소거 토글을 관전 화면에 둔다. `prefers-reduced-motion`과는 별개 설정이다.

## 3-6. 샘플 예산 — 14개로 시작

파일 수를 최소로 유지한다. 피치·볼륨 랜덤화로 변화를 만든다.

```
총성 4   carbine / smg / marksman / bolt
피격 2   몸 / 머리
탄착 1   벽
폭발 2   수류탄 / 파쇄
이동 1   발소리
장치 2   설치 시작 / 해체 완료
UI   2   라운드 시작 / 라운드 종료
----------
합계 14
```

각 샘플에 `playbackRate` ±6%, `gain` ±2dB 랜덤을 주면 반복감이 사라진다. 소음기 무기(MP5SD, AS Val)는 같은 샘플에 lowpass 1.2kHz + gain −9dB로 만든다. 별도 녹음이 필요 없다.

OGG/MP3 48kHz mono, 샘플당 20~60KB, **합계 500KB 이하**를 목표로 한다. 현재 번들이 JS 457KB이므로 비슷한 규모다.

## 3-7. 구조

오디오는 렌더러에 넣지 않는다. 별도 모듈로 두고 `BroadcastCanvas`가 프레임마다 새 사건만 넘긴다.

```
domain/realtime/  ← 사건 생성 (변경 없음)
        ↓ events
components/matchAudio.ts  ← 신규. 사건을 받아 큐에 넣고 믹싱
        ↓ Web Audio
```

```ts
/** 사건 로그를 중계 오디오로 바꾼다. 엔진 판정과 사건 내용은 변경하지 않는다. */
export function createMatchAudio(load: (name: string) => AudioBuffer | undefined) {
  const ctx = new AudioContext();
  const master = ctx.createGain(); master.connect(ctx.destination);
  const lastStep = new Map<string, number>();   // 유닛별 마지막 발소리 시각
  let playing = 0;

  /** 카메라 기준 거리와 벽으로 음량·저역을 정한다. 선수 위치가 아니라 카메라가 기준이다. */
  function place(position: TacticalPoint, camera: Rect, occluded: boolean) {
    const cx = camera.x + camera.width/2, cy = camera.y + camera.height/2;
    const reach = camera.width * 0.7;
    const d = Math.hypot(position.x - cx, position.y - cy);
    const gain = Math.max(0, 1 - (d/reach)**2) * (occluded ? 0.45 : 1);
    const pan = Math.max(-1, Math.min(1, (position.x - cx) / (camera.width/2)));
    return { gain, pan, lowpass: occluded ? 600 : 18000 };
  }
  // 이하 큐 처리·동시 발음 제한·배속별 필터
}
```

## 3-8. 작업 순서

| 순서 | 내용 | 확인 방법 |
|---|---|---|
| 1 | `matchAudio.ts` 골격 + unlock + 음소거 토글 | 출전 후 무음이어도 에러 없음 |
| 2 | 총성 4종 + 피격 2종 (우선순위 1) | 교전에서 소리가 남 |
| 3 | 폭발·파쇄·장치·UI 스팅어 | 결정적 순간에 소리가 남 |
| 4 | 발소리 + 3단 감쇠·병합 | 초당 발음 수를 로그로 확인 |
| 5 | 배속별 재생 대상 분기 | 4배속에서 찍찍거리지 않음 |
| 6 | 소음기 필터 변형 | COLLIER 교전이 조용함 |

1~3단계까지만 해도 "밋밋함"의 절반이 해결된다. 발소리는 가장 까다롭고 효과는 가장 작으니 마지막에 둔다.
