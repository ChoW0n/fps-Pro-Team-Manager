# 선수 AI 보는 재미 — Phase A/B 구현 기록

기준: `fix/qa-complete-coverage`의 `78e1796` 위 작업. 전달받은 `spec-ai-behavior-fun-first.md`의 순서를 따라 Phase A 다음 Phase B까지만 구현했다. Phase C는 A/B의 외부 화면 검증 뒤 진행한다.

## 구현

- 근거리 표적 획득 시간에 거리 항을 추가했다. 6경기 공격 승률이 33.3%로 측정되어 명세의 보정 조건대로 근거리 계수는 `.38`에서 `.28`로 한 번 조정했다.
- `shotCone`에 이동 직후 정착 부족 항 `max(0, .3-settled)*.09`를 추가했다. 무기별 기본 cone과 damage, 결과 확률은 변경하지 않았다.
- 오퍼레이터를 속도 44/52/62와 체력 125/100/80의 세 계층으로 나눴다. 선수 `teamSynergy/20`은 기존처럼 이동 속도에 남겼다.
- 주요 분기에 `decision`을 연결했다. 진입 대기·선두·후속 엄호·후퇴·압박 회피·장거리 우회·소리 추적·로머·앵커·가젯·장전·구조를 포함한다.
- 중계 선수 카드의 `goal` 한 줄을 제거하고, 같은 판단이 바뀔 때만 최근 3개를 쌓는 독립 하단 피드를 추가했다. 전술 보기에서 피드를 숨기지 않는다.
- 체력 막대의 최대값은 각 오퍼레이터의 `maxHp`를 사용한다.

## 자동 검증 결과

`tests/fun-first-ai-audit.cjs 12`의 고정 편성·다섯 진입로 표본:

| 지표 | 결과 | 목표 | 판정 |
|---|---:|---:|---|
| 명중률 | 92.7% | 60% 이하 | 실패 |
| 헤드샷 비율 | 11.2% | 12% 이하 | 통과 |
| 라운드 사망 중앙값 | 7명 | 4~5명 | 실패 |
| 한 선수 4킬 이상 | 0% | 12% 이하 | 통과 |
| 공격 속도 편차 중앙값 | 32.2% | 25% 이상 | 통과 |
| 공격 승률 | 33.3% | 40~60% | 실패 |

| 판단 공백 유닛-틱 | 0% | 15% 이하 | 통과 |

현재 명중 실패는 숨기지 않는다. 새 정착 항은 이동 직후에만 작동하지만 현재 교전은 표적 획득 중 정지한 뒤 발사되는 경우가 많아, 발사 시점에는 추가 항이 사라진다. 명세에서 금지한 기본 무기 탄퍼짐·피해량·결과 확률 보정은 적용하지 않았다.

기존 `qa-verify.cjs 6`은 38개 중 24 통과, 11 실패, 3 보류였다. 이 중 Phase A/B와 직접 관련된 결과는 공격 승률 33.3%, 명중률 91.0%, 헤드 9.9%, 4킬 이상 0%, 첫 사망 중앙값 43.8초다. 표본과 편성이 달라 전용 12경기 결과와 합치지 않는다.

회귀는 `fun-first-ai`, 준비 UI 계약, 실시간 엔진, combat-overhaul, tactical-match, TypeScript 검사와 production build를 통과했다. 기존 tactical-match의 시작 체력 100 고정 검사는 새 규칙에 맞춰 `hp === maxHp`로 바꾸고, 정확한 계층값은 `fun-first-ai`에서 별도로 검사한다.

## 외부 화면 검증 전달 항목

Codex는 사용자 결정에 따라 브라우저 검증을 실행하지 않는다. 사용자·Claude가 확인할 항목은 다음 두 가지다.

1. 근거리 조우에서 첫 탄 전 지연과 44/52/62 속도 차이가 실제 화면에서 읽히는지
2. 하단 최근 3개 판단이 전술 보기에서도 유지되고 같은 문장이 반복해 쌓이지 않는지

외부 결과를 받은 뒤 Phase A의 남은 치명성 원인을 조정할지, 명세 권장대로 Phase C 진입 대형으로 넘어갈지 결정한다.
