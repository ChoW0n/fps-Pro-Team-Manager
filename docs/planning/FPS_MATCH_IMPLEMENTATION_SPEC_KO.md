## 0. 이 문서의 사용법

이 문서는 아이디어 모음이 아니라 **구현 계약서**다. 각 기능은 아래 네 요소를 반드시 만족해야 완료로 판정한다.

| 항목 | 의미 |
|---|---|
| 목표 | 이 기능이 경기 경험에서 해결해야 하는 문제 |
| 화면 결과 | 플레이어가 실제 경기 화면에서 확인해야 하는 상태 |
| 실패 위험 | 구현 중 자주 생기는 오류와 잘못된 타협 |
| 검수 기준 | QA가 합격·불합격을 판정할 수 있는 조건 |

`필수`는 첫 출시 범위, `확장`은 필수 기반이 안정된 뒤 추가한다. 수치는 초기 기준값이며 데이터 파일에서 조정할 수 있어야 한다. 판정·AI·리플레이·중계 연출은 서로 직접 상태를 수정하지 않고 경기 이벤트를 통해 연결한다.

## 1. 제품 정의와 창작 원칙

### 1.1 한 문장 정의

선수의 능력, 오퍼레이터 조합, 사전 전술과 현장 판단이 **5대5 무리스폰 라운드**에서 실제 움직임으로 드러나고, 사용자는 이를 스포츠 중계처럼 이해하며 구단 운영의 결과를 납득하는 게임이다.

### 1.2 핵심 경험 목표

1. **전술 가독성**: 3초 안에 누가 어느 팀이고, 어디를 보고 있으며, 무엇을 시도하는지 알 수 있다.
2. **선수 서사**: 동일한 오퍼레이터라도 선수의 에임, 침착성, 역할 수행, 실수가 구분된다.
3. **고치명도 긴장감**: 한 번의 정보 획득·각도 실수·교환 사격이 라운드 흐름을 바꾼다.
4. **방송 완성도**: 카메라는 결과가 아닌 원인을 먼저 보여주고, 중요한 교전을 놓치지 않는다.
5. **고증과 창작의 균형**: 총기 작동, 장비 배치, 복장 구조는 현실적이되 인물·부대 표식·고유 장비·UI는 독자 디자인을 사용한다.

### 1.3 금지 사항

- 특정 상용 게임의 로고, 오퍼레이터 이름·초상·고유 장비, 아이콘, 색 배치, HUD 구조, 맵 동선을 1:1로 복제하지 않는다.
- 실제 부대 마크와 제조사 로고는 라이선스 확인 없이 사용하지 않는다. 복장은 장비 체계와 착용 논리만 참고하고 표식은 허구화한다.
- 카메라 연출을 위해 명중 판정, AI 의사결정, 탄도 결과를 바꾸지 않는다.
- 정보가 없는 적을 팀 전술 UI에 실시간 표시하지 않는다. 전지적 방송 정보와 팀이 획득한 정보를 시각적으로 구분한다.
- 타격감을 만들기 위해 경기 시뮬레이션 자체를 슬로모션하거나 정지하지 않는다.

### 1.4 기준 참고

원작 참고점은 고치명도 근접전, 파괴 가능한 공간, 장비 중심 역할 구분이다. 세부 수치와 표현은 본 프로젝트용으로 재설계한다. 참고 링크: [Ubisoft 공식 게임 소개](https://www.ubisoft.com/en-au/game/rainbow-six/siege), [Ubisoft 공식 오퍼레이터 분류](https://www.ubisoft.com/en-us/game/rainbow-six/siege/game-info/operators).

## 2. 경기의 기술 구조

### 목표

같은 입력과 시드에서 같은 결과가 재현되고, 중계 카메라·HUD·리플레이가 판정 로직과 분리되어야 한다.

### 필수 구조

| 계층 | 책임 | 갱신 기준 |
|---|---|---|
| Match Authority | 시간, 승패, 피해, 탄도, 충돌, 목표물 판정 | 고정 20 Hz |
| Tactical AI | 인지, 계획, 이동·사격 의도 생성 | 5~10 Hz, 상황별 분산 |
| Knowledge Model | 팀·선수별 확인/추정/소실 정보 | 이벤트 기반 |
| Presentation | 보간, 애니메이션, 이펙트, 사운드 | 최대 60 fps |
| Broadcast Director | 카메라 후보 평가, 컷, 리플레이 | 5 Hz + 핵심 이벤트 |
| Replay Log | 시드, 명령, 판정 이벤트, 상태 체크섬 | 전 라운드 기록 |

### 화면에서 보여야 할 결과

- 프레임이 떨어져도 선수 이동 속도, 발사 수, 피해량, 라운드 시간이 달라지지 않는다.
- 20 Hz 상태 사이를 렌더러가 보간해 이동이 부드럽다.
- 라운드 재생과 즉시 리플레이의 킬 순서·탄약·목표물 상태가 원본과 일치한다.

### 실패하기 쉬운 지점

- `deltaTime`에 피해·발사·AI 결정을 직접 묶어 고사양과 저사양 결과가 달라짐.
- 카메라가 선택한 대상을 AI가 우선 공격하는 등 프레젠테이션이 시뮬레이션에 역영향을 줌.
- 리플레이를 좌표 녹화만으로 만들고 파괴물·탄약·정보 상태를 누락함.

### 검수 기준

- 동일 시드 100회 재실행의 최종 승자, 생존자, 킬 순서, 설치 시각 체크섬이 100% 동일하다.
- 렌더 30/60/120 fps 강제 조건에서 판정 결과가 동일하다.
- 한 라운드 리플레이 탐색 후 원본 시각으로 복귀했을 때 상태 체크섬이 일치한다.

## 3. 5대5 무리스폰 경기 규칙

### 3.1 기본 경기 형식

| 항목 | 기본값 | 구현 규칙 |
|---|---:|---|
| 인원 | 공격 5 / 방어 5 | 라운드 중 신규 투입·리스폰 없음 |
| 규정 라운드 | 최대 12 | 7라운드 선취 시 종료 |
| 공수 교대 | 6라운드 후 | 스폰, 목표 방, UI 좌우 위치 함께 교대 |
| 연장 | 6:6 시 최대 3라운드 | 공수 시작 측은 경기 전 시드로 결정, 2선취 |
| 전술 잠금 | 15초 | 출전 선수·오퍼레이터·장비·초기 계획 확정 |
| 준비 단계 | 35초 | 방어 설치, 공격 정찰; 직접 교전 불가 |
| 행동 단계 | 160초 | 진입, 교전, 목표 장치 설치 가능 |
| 설치 행동 | 6초 | 중단 시 진행도 초기화 |
| 설치 후 제한 | 45초 | 방어 측 해제 완료 전 폭발 시 공격 승리 |
| 해제 행동 | 7초 | 피격·이동·사망 시 중단 |
| 라운드 종료 연출 | 7초 | 판정 고정, 결과·핵심 장면 표시 |

모든 시간은 `MatchRules` 데이터로 노출한다. UI에 표시되는 시간은 권위 타이머를 내림 표시하며, 로컬 애니메이션 시간으로 계산하지 않는다.

### 3.2 라운드 상태 기계

`TACTIC_LOCK → PREP → ACTION → DEVICE_ACTIVE → ROUND_RESOLVE → ROUND_END → SIDE_SWAP/MATCH_END`

- `TACTIC_LOCK`: 로스터와 장비 검증 실패 시 이전 유효 구성을 사용하고 경고를 남긴다.
- `PREP`: 방어팀은 설치·보강, 공격팀은 정찰 정보를 축적한다. 사망·피해 판정은 비활성화한다.
- `ACTION`: 교전과 목표 설치가 모두 가능하다.
- `DEVICE_ACTIVE`: 행동 단계 타이머를 폐기하고 장치 타이머만 사용한다.
- `ROUND_RESOLVE`: 동시 이벤트를 한 틱 안에서 우선순위로 해석하고 승자를 한 번만 확정한다.
- `ROUND_END`: AI와 탄도 생성을 중단하되 화면상의 잔향·탄피·먼지는 자연스럽게 마무리한다.

### 3.3 승패 판정 우선순위

한 시뮬레이션 틱에 사건이 겹칠 경우 다음 순서로 판정한다.

1. 설치 완료 또는 해제 완료 같은 **완료 이벤트**를 틱 타임스탬프로 확정한다.
2. 이미 설치된 장치가 제한 시각에 도달했으면 공격 승리다.
3. 장치 미설치 상태에서 공격 전멸이면 방어 승리다.
4. 장치 미설치 상태에서 방어 전멸이면 공격 승리다.
5. 행동 시간 종료 시 장치 설치가 완료되지 않았으면 방어 승리다.
6. 장치 설치 후 공격팀이 전멸해도 라운드는 계속된다. 생존 방어팀이 해제해야 승리한다.
7. 양 팀 최후 인원이 같은 틱에 사망하면 장치 상태로 판정한다. 미설치면 방어, 설치 상태면 공격 승리다.

승리 사유는 `ELIMINATION`, `TIME`, `DEVICE_DETONATED`, `DEVICE_DISABLED` 중 하나로 저장한다.

### 3.4 생존 상태

- `ACTIVE`: 이동·사격·장비 사용 가능.
- `INCAPACITATED`: 이동 제한, 사격 불가, 20초 출혈 타이머. 아군의 7초 구조로 20 체력 복귀.
- `DEAD`: 해당 라운드 행동 종료. 다음 라운드에만 복귀.
- 헤드 치명타, 큰 폭발, 출혈 중 추가 피해는 바로 `DEAD` 처리한다.
- 같은 라운드에서 구조된 인원은 다시 쓰러질 경우 즉사한다.

### 화면에서 보여야 할 결과

- 사망 선수 카드는 사라지지 않고 흑백·사망 표식으로 남아 현재 5대5 구도가 4대3 등으로 즉시 읽힌다.
- 설치 이후 공격 전멸 장면에서도 장치 타이머와 해제 가능성이 계속 강조된다.
- 공수 교대 시 팀 고유색은 유지하고 공격·방어 역할 아이콘만 바뀐다.

### 실패하기 쉬운 지점

- 마지막 방어 사망과 설치 완료가 겹칠 때 이벤트 호출 순서에 따라 승자가 달라짐.
- 사망 오브젝트를 제거해 킬 로그·리플레이 참조가 깨짐.
- 공수 교대 때 UI 색과 스폰만 바뀌고 전술·목표 지식이 이전 라운드에서 누출됨.

### 검수 기준

- 위 7개 승패 경계 상황을 자동 테스트로 각각 20회 실행해 결과가 고정된다.
- 라운드 중 사망한 선수는 어떤 효과로도 `ACTIVE`로 돌아오지 않는다.
- 6라운드 종료 후 정확히 한 번만 공수 교대가 발생하고 점수·팀 정체성은 유지된다.

## 4. 경기 공간, 축척, 충돌과 파괴

### 목표

맵·통로에 비해 캐릭터가 두껍거나 장비가 떠 보이지 않으며, 총구와 엄폐물이 실제 공간 관계를 가진다.

### 축척 기준

| 요소 | 월드 기준 | 탑뷰 검수 비율 |
|---|---:|---|
| 성인 캐릭터 키 | 1.72~1.88 m | 장신·단신 차이는 ±4% 이내로 제한 |
| 충돌 캡슐 지름 | 0.42 m | 0.9 m 문 폭의 47% 이하 |
| 시각적 어깨 폭 | 0.44~0.52 m | 표준 문 폭의 49~58% |
| 표준 문 | 0.90 m | 두 명 동시 통과 불가, 교차는 가능 |
| 좁은 복도 | 1.20~1.45 m | 1열 이동, 추월 시 속도 저하 |
| 일반 복도 | 1.80~2.40 m | 2인 교차와 제한적 나란히 이동 가능 |
| 얇은 벽 | 0.10~0.16 m | 탄종별 관통·파괴 가능 |

### 공간 규칙

- 캐릭터 충돌, 피격 히트박스, 선택 UI 범위를 분리한다. 선택 범위 확대가 통로를 막아서는 안 된다.
- 무기는 캐릭터 충돌을 확장하지 않지만 총구가 벽을 통과하면 발사 원점을 벽 앞까지 보정하거나 사격을 제한한다.
- 문·창·바리케이드·보강벽·바닥 해치는 상태형 오브젝트로 관리한다.
- 파괴는 `INTACT → DAMAGED → OPEN` 3단계를 기본으로 하며, 시각 타일·LOS·탄도·길찾기 갱신을 한 이벤트로 묶는다.
- 다층 맵은 층마다 독립 내비게이션 그래프를 갖고 계단·사다리·해치 노드로 연결한다.

### 화면에서 보여야 할 결과

- 표준 문을 통과할 때 어깨가 문틀을 뚫거나 몸 전체가 문을 채우지 않는다.
- 벽이 열리면 1틱 안에 시야와 탄도가, 5틱 안에 AI 길찾기가 새 통로를 반영한다.
- 위층 인원은 현재 층에서 실루엣 또는 그림자로만 표시되며 실제 바닥 위에 떠 있는 것처럼 보이지 않는다.

### 실패하기 쉬운 지점

- 스프라이트 외곽을 충돌체로 써 방탄복·백팩 때문에 캐릭터가 비정상적으로 넓어짐.
- 파괴 그래픽만 바뀌고 LOS 또는 내비게이션이 갱신되지 않음.
- 총구가 캐릭터 중심에서 발사되어 엄폐 뒤에서도 탄이 벽을 무시함.

### 검수 기준

- 10명이 표준 문 20개와 복도 3종을 통과하는 스트레스 테스트에서 끼임·겹침·영구 정지 0건.
- 파괴 전후 동일 사격선 테스트에서 LOS, 관통, AI 경로 결과가 설계값과 일치한다.
- 모든 총기 자세에서 총구 좌표가 손·총열과 오차 4 px 또는 0.04 m 이내다.

## 5. 시야·정보·소리 인지

### 목표

선수가 보는 것, 팀이 공유한 것, 방송이 보여주는 것을 분리해 잠입·정찰·오판이 경기 서사로 드러나게 한다.

### 5.1 세 가지 정보층

| 층 | 내용 | 화면 표현 |
|---|---|---|
| Authority | 모든 실제 위치·상태 | 개발 디버그 외 직접 노출 금지 |
| Team Knowledge | 목격, 카메라, 핑, 소리 추정으로 획득한 적 정보 | 실선=현재 확인, 점선=최근 확인, 원형 음영=소리 추정 |
| Broadcast | 관중 이해를 위한 전지적 정보 | 얇은 팀색 외곽선과 방송 전용 라벨; 팀 정보와 다른 형태 |

### 5.2 시각 인지

- 기본 수평 시야각 95°, 집중 조준 시 55°, 주변 경계 상태 115°를 기준으로 한다.
- 가시 판정은 눈 위치에서 대상의 머리·흉부·골반 3개 샘플로 실시한다. 2개 이상 가시이면 완전 식별, 1개면 부분 감지다.
- 적 식별 시간은 거리·노출 면적·이동·조명·선수 인지 능력으로 0.12~0.75초 범위에서 계산한다.
- 연막은 누적 광학 밀도로 LOS를 감쇠한다. 연막 가장자리 한 점만 통과했다고 즉시 완전 차단하지 않는다.
- 마지막 확인 위치는 기본 3초간 유지하고 정확도 원을 시간당 확대한다. 벽 너머에서 적을 따라 움직이지 않는다.
- 카메라·드론·센서는 소유 팀의 Knowledge에만 갱신 이벤트를 보낸다.

### 5.3 소리 인지

- 발걸음, 질주, 재장전, 장비, 파괴, 발사는 `강도·주파수대·발생 층·표면·공간` 정보를 가진다.
- AI는 정확한 좌표 대신 오차 반경을 가진 소리 추정치를 얻는다. 벽·문·층 연결에 따라 감쇠·회절한다.
- 동일 소리를 모든 선수가 동시에 정확히 아는 방식은 금지한다. 개인 인지 후 통신 지연을 거쳐 팀에 공유한다.

### 화면에서 보여야 할 결과

- 방송 모드에서는 양 팀 실루엣을 볼 수 있지만, 아직 발견하지 못한 적은 해당 팀의 전술 핑·에임 반응에 영향을 주지 않는다.
- 최근 위치는 잔상이나 점선 링으로 남고 시간이 지나면 흐려져 사라진다.
- 소리 추정은 적 아이콘이 아니라 방향성 파동·불확실 영역으로 보인다.

### 실패하기 쉬운 지점

- 중앙점 하나로 LOS를 판정해 발끝만 보여도 완전 식별하거나 난간 뒤 상체를 못 봄.
- 방송용 X-ray 좌표를 AI가 공유해 벽 너머 추적이 발생함.
- 위층 총성이 같은 층의 정확한 위치 핑으로 표시됨.

### 검수 기준

- 20개 엄폐 샘플에서 완전·부분·비가시 판정이 기획 라벨과 95% 이상 일치한다.
- 미발견 적이 벽 뒤에서 10초 이동해도 상대 에임·경로가 실시간 좌표를 추종하지 않는다.
- 층·문 상태별 소리 30종 테스트에서 추정 방향과 오차 반경이 데이터 허용 범위 안이다.

## 6. 선수 AI와 전술 행동

### 목표

선수 능력치와 감독 전술이 눈에 보이는 행동 차이로 이어지고, AI가 킬을 위해 전지적 정보나 비현실적 반응을 사용하지 않는다.

### 6.1 역할 모델

각 선수는 한 경기에서 `ENTRY`, `SUPPORT`, `BREACH`, `ROAM`, `ANCHOR`, `FLEX` 중 주 역할과 보조 역할을 가진다. 역할은 능력치 보너스가 아니라 **행동 우선순위 묶음**이다.

- ENTRY: 공간 진입, 첫 접촉, 트레이드 가능한 거리 유지.
- SUPPORT: 장비 보존, 정보 공유, 목표 장치 운반·설치.
- BREACH: 개방 지점 선정, 파괴 순서, 엄호 요청.
- ROAM: 시간 소모, 퇴로 보존, 고립 회피.
- ANCHOR: 목표 지역 생존, 교차각 유지, 설치 저지.
- FLEX: 인원 손실과 계획 실패 시 빈 역할 승계.

### 6.2 의사결정 순서

1. 생존 위협: 즉시 엄폐, 사선 이탈, 근거리 대응.
2. 라운드 강제 조건: 시간, 목표 장치, 설치·해제 저지.
3. 팀 계획: 진입로, 합류 시각, 장비 연계, 교차각.
4. 정보 가치: 정찰, 소리 확인, 미확인 구역 클리어.
5. 개인 기회: 유리한 피킹, 우회, 추격.

AI는 0.1~0.35초의 인지·결정 지연을 가지며, 선수의 반응·침착성·소통 능력으로 변동한다. 적 좌표가 아닌 지식 기록을 입력으로 사용한다.

### 6.3 교전 규칙

- 진입자와 트레이더의 목표 간격은 2.5~5.5 m, 시간 차는 0.4~1.5초다.
- 아군 사선 앞을 횡단하기 전 0.2초 예측 충돌을 검사한다.
- 연사 길이는 거리·반동·탄약·표적 노출에 따라 2~12발로 제한한다.
- 탄창 잔량이 적어도 즉시 위험·목표 시간·아군 엄호가 우선이며, 안전하지 않은 자동 재장전을 금지한다.
- 마지막 적의 실제 위치를 모르면 클리어 순서에 따라 탐색한다. 결과를 알고 직행하지 않는다.

### 화면에서 보여야 할 결과

- 같은 계획에서도 노련한 선수는 각도 노출이 짧고, 트레이드 거리를 유지하며, 장비를 필요한 시점까지 보존한다.
- 패배 원인이 “에임 수치가 낮아서”만이 아니라 늦은 합류, 정보 오판, 장비 낭비 등 행동으로 읽힌다.
- 팀 전술이 깨지면 FLEX가 비어 있는 임무를 맡고 HUD에 역할 승계가 짧게 표시된다.

### 실패하기 쉬운 지점

- 역할을 고정 경로로 만들어 상황이 변해도 ENTRY가 혼자 돌진함.
- 위협 점수 하나로 모든 행동을 골라 설치 2초 전 재장전 같은 비상식이 발생함.
- 에임 성능 차이를 명중률 난수만으로 처리해 선수 개성이 보이지 않음.

### 검수 기준

- 공격 시나리오 100회에서 고립된 선행 진입 비율 12% 이하, 계획된 트레이드 거리 준수 80% 이상.
- 정보가 삭제된 대조 실험에서 AI가 숨은 적의 방을 통계적으로 유의하게 더 자주 선택하지 않는다.
- 선수 능력치 상·중·하 세 그룹의 반응 시간, 조준 안정, 장비 보존 지표가 의도한 순서로 분리된다.

## 7. 중계 카메라

### 목표

카메라는 항상 “무슨 일이 일어났는가”보다 “왜 곧 일어나는가”를 먼저 보여주며, 10명의 위치 관계와 결정적 교전을 함께 전달한다.

### 7.1 카메라 모드

| 모드 | 사용 조건 | 화면 구성 |
|---|---|---|
| Strategic Wide | 교전 가능성 낮음, 재배치 중 | 한 층의 6명 이상 또는 양 팀 전선을 포함 |
| Team Setup | 동시 진입·수비 설치 | 한 팀 3명 이상과 목표 지점을 포함 |
| Contact | 3초 내 상호 LOS 가능 | 교전 양측, 엄폐, 진입로가 모두 보이게 2~5명 프레이밍 |
| Duel Focus | 실제 사격 교환 | 두 선수와 탄도 방향이 보이는 중근거리 줌 |
| Objective | 설치·해제·저지 | 행동자, 장치, 가장 가까운 위협을 포함 |
| Clutch | 1대N 또는 최후 생존자 | 생존자 중심, 위협 수와 남은 시간 강조 |
| Replay | 라운드 종료 후 핵심 장면 | 원본 판정 로그 기반 4~8초 재생 |

### 7.2 자동 디렉터 점수

각 후보 영역의 점수는 아래 합으로 계산한다.

`Score = 교전예측 35 + 목표중요도 25 + 인원밀도 15 + 스타선수 8 + 장비연계 7 + 서사연속성 10 - 반복피로 - 급격이동 - 정보누설`

- 최소 샷 유지 2.5초, 일반 최대 8초.
- 실제 발사·설치 시작 후 0.7초 동안 불필요한 컷 금지.
- 더 높은 후보가 현재보다 25점 이상이거나 킬·설치 완료 이벤트일 때만 강제 전환.
- 카메라 중심은 현재 위치가 아니라 0.6초 예측 교전 중심을 향한다.
- 패닝 속도는 화면 폭 기준 초당 0.35~0.9, 줌 변화는 초당 18% 이하. 긴급 컷은 이동 없이 즉시 전환한다.

### 7.3 탑뷰 구도

- 기본 투영은 72~78° 기울기의 준직교 탑뷰. 순수 수직 시점보다 벽 높이와 자세를 읽을 수 있어야 한다.
- 캐릭터 화면 높이 기본 42~64 px, 교전 줌 70~96 px, 전략 줌 24~38 px.
- 이동 방향보다 **조준 방향 앞쪽**에 35% 더 많은 여백을 둔다.
- 총구, 표적, 엄폐 모서리 중 하나라도 HUD에 가리면 프레이밍을 재조정한다.
- 다층 교전에서는 현재 초점 층을 실색, 인접 층을 25% 명도 윤곽으로 표시한다. 지붕·천장은 카메라와 초점 사이일 때만 페이드한다.
- 카메라 회전은 기본 고정 북쪽 위. 리플레이 또는 좁은 실내 연출에서도 최대 ±15°만 허용한다.

### 7.4 수동 관전

- 선수 카드 클릭: 해당 선수 추적.
- 빈 공간 드래그: 자유 카메라, 5초 무입력 후 자동 디렉터 복귀 선택 가능.
- 마우스 휠·핀치: 전략/교전 줌 범위 내 확대.
- 층 버튼 또는 단축키: 현재 층 고정.
- `방송`, `팀 정보`, `전술 분석` 세 표시 모드를 제공하며 경기 판정에는 영향이 없다.

### 화면에서 보여야 할 결과

- 킬 직전 최소 1초 동안 공격자 또는 피격자의 접근·각도가 화면 안에 존재한다.
- 설치 장면은 설치자만 확대하지 않고 접근하는 수비수와 차단 장비까지 보여준다.
- 컷이 바뀌어도 팀 방향, 층, 방 이름을 0.8초 내 재인식할 수 있다.

### 실패하기 쉬운 지점

- 가장 가까운 두 선수만 확대해 제3의 트레이더와 장비 연계를 잘라냄.
- 카메라가 킬 이벤트 뒤에 이동해 사망 결과만 보여줌.
- 벽·천장 페이드가 너무 넓어 맵 구조가 사라지거나, 너무 좁아 총격을 가림.
- 빈번한 줌·회전으로 스포츠 중계가 아니라 화면 흔들림처럼 느껴짐.

### 검수 기준

- 자동 경기 20회, 전체 킬의 90% 이상에서 가해자·피해자 또는 탄도 진입 방향이 킬 1초 전 화면에 있다.
- 설치·해제 100%에서 행동자, 장치, 5초 내 도달 가능한 가장 가까운 적이 프레임 또는 미니 전술창에 보인다.
- 60초 구간 일반 컷 6~14회, 2초 미만 샷은 강제 이벤트 외 5% 이하.
- 카메라가 UI 안전 영역을 침범해 핵심 대상이 가려지는 프레임 0건.

## 8. 경기 중계 인터페이스

### 목표

사용자가 시선을 크게 이동하지 않고 점수·인원·시간·목표·선수 정체·현재 사건을 읽으며, 화면 중앙의 전술 행동은 가리지 않는다.

### 8.1 1920×1080 기준 배치

| 영역 | 위치·크기 | 필수 정보 |
|---|---|---|
| 상단 스코어 바 | x 300~1620, y 20~88 | 팀명/엠블럼, 세트·라운드 점수, 공수, 타이머, 라운드 번호 |
| 좌측 로스터 | x 24~268, y 124~604 | A팀 선수 5명, 오퍼레이터, 체력, 장비, 생존 상태 |
| 우측 로스터 | x 1652~1896, y 124~604 | B팀 동일 정보, 읽기 방향만 대칭 |
| 킬 피드 | x 1280~1896, y 112~260 | 최근 4건, 가해/피해/무기/보조 여부 |
| 목표 카드 | x 760~1160, y 92~150 | 장치 운반·설치·해제, 진행도, 경고 |
| 포커스 카드 | x 40~600, y 880~1040 | 선택 선수의 닉네임, 역할, 무기, 탄약, 주요 능력치·현재 행동 |
| 전술 미니맵 | x 1530~1888, y 790~1038 | 현재 층, 방 이름, 팀 지식 기반 핑; 접기 가능 |
| 이벤트 자막 | x 640~1280, y 820~900 | 클러치, 연속 처치, 설치 시작 등 1개 사건만 |

화면 외곽 24 px, 상·하 방송 안전 영역 5%를 확보한다. 1366×768에서는 로스터 폭을 196 px로 줄이고 포커스 카드의 능력치 문장을 아이콘으로 축약한다. 1024 px 미만은 관전 전용 축약 UI로 전환하며 개발·밸런스 기준 해상도에서는 제외한다.

### 8.2 정보 우선순위

1. 승패를 바꾸는 정보: 시간, 인원, 장치.
2. 현재 사건: 누가 누구와 싸우는지, 설치·해제 진행.
3. 선수 식별: 닉네임, 오퍼레이터, 역할, 생존.
4. 자원: 탄약, 고유 장비, 투척물.
5. 분석 정보: 확률, 기대 승률, 피로, 폼.

분석 정보는 기본 경기 HUD에 계속 띄우지 않고 전술 분석 모드 또는 라운드 종료 화면에서 제공한다.

### 8.3 색과 접근성

- 팀색은 청록/주황을 기본으로 하되 색만으로 구분하지 않는다. A팀은 원형 표식, B팀은 마름모 표식을 함께 사용한다.
- 공수는 검/방패 아이콘과 `공격`, `방어` 텍스트를 병기한다.
- 생존/부상/사망은 형태, 명도, 패턴이 모두 달라야 한다.
- 일반 본문 대비 4.5:1, 큰 글자·핵심 아이콘 3:1 이상.
- 화면 흔들림, 섬광, 혈흔, X-ray, 자동 카메라 컷 빈도는 각각 조절 가능해야 한다.

### 화면에서 보여야 할 결과

- 팀 고유색은 공수 교대 후에도 바뀌지 않는다.
- 선수 카드 하나만 보고 닉네임, 오퍼레이터, 체력, 생존, 남은 고유 장비를 판독할 수 있다.
- 킬 피드는 6초 유지하되 같은 사건의 지원 정보는 한 줄로 합친다.
- 설치가 시작되면 목표 카드가 타이머보다 한 단계 앞 레이어로 올라오지만 전장을 가리지 않는다.

### 실패하기 쉬운 지점

- 팀색과 공수색을 동일 개념으로 사용해 교대 때 정체성이 뒤집힘.
- 모든 정보를 항상 표시해 작은 글자와 아이콘 소음이 생김.
- 사망 카드를 제거해 현재 인원 차를 세어야 함.
- 킬 피드가 실제 판정보다 먼저 떠 총알 도착과 결과가 어긋남.

### 검수 기준

- 1920×1080, 1366×768에서 핵심 HUD 겹침·잘림 0건.
- 색각 이상 시뮬레이션 3종에서 팀과 상태를 형태만으로 100% 구분한다.
- 처음 보는 테스트 참여자 5명 중 4명 이상이 3초 안에 점수, 남은 시간, 생존 인원, 장치 상태를 정확히 답한다.

## 9. 선수와 오퍼레이터 식별 체계

### 목표

“누가 플레이하는가”와 “어떤 전투 역할을 수행하는가”를 동시에 읽히게 하되, 인물·오퍼레이터·팀 색이 서로 경쟁하지 않게 한다.

### 식별 계층

| 우선 | 식별 대상 | 표현 |
|---:|---|---|
| 1 | 팀 | 외곽 링 색 + 원/마름모 형태 |
| 2 | 선수 | 3~10자 닉네임, 고정 등번호 |
| 3 | 오퍼레이터 | 독자 콜사인, 얼굴/헬멧 실루엣, 역할 아이콘 |
| 4 | 상태 | 체력, 부상, 사망, 설치자, 장치 운반자 |
| 5 | 장비 | 주무기 실루엣, 고유 장비 잔량 |

- 월드 라벨은 전략 줌에서 닉네임만, 교전 줌에서 닉네임+오퍼레이터 약칭을 보여준다.
- 카드 초상은 얼굴보다 헤드기어·고글·마스크·목 장비의 큰 형태 차이를 우선한다.
- 팀 유니폼은 몸통 60% 이하에만 팀색을 사용한다. 전신을 원색으로 칠하지 않는다.
- 오퍼레이터 역할은 색이 아니라 아이콘 외곽 형태로 구분한다: 돌파=쐐기, 정보=눈금 원, 차단=벽, 지원=십자 결합형.

### 화면에서 보여야 할 결과

- 같은 유니폼을 입은 5명도 머리·어깨·등 장비 실루엣과 번호로 구분된다.
- 오퍼레이터를 교체해도 선수 닉네임과 등번호는 유지되어 시즌 서사가 끊기지 않는다.
- 줌 아웃 시 텍스트가 겹치면 중요도 순으로 장치 운반자→현재 교전자→선택 선수→나머지 라벨을 숨긴다.

### 실패하기 쉬운 지점

- 얼굴 디테일에만 의존해 탑뷰에서 모두 같은 원형 머리로 보임.
- 오퍼레이터별 색을 과도하게 써 팀 식별이 약해짐.
- 실제 부대 패치를 그대로 사용해 창작 정체성과 권리 문제가 생김.

### 검수 기준

- 무채색 화면과 50% 축소 화면에서도 10명 전원의 팀을 100%, 같은 팀 내 개체를 80% 이상 구분한다.
- 일반 카메라 높이에서 닉네임 텍스트 겹침 프레임이 전체의 2% 이하이며 핵심 행동자 라벨은 100% 유지된다.

## 10. 캐릭터·총기·장비·복장 고증

### 10.1 캐릭터 비율과 탑뷰 스프라이트

#### 목표

맵에 비해 캐릭터가 뚱뚱하고 총을 겨드랑이에 끼운 인형처럼 보이는 문제를 제거한다.

#### 구현 기준

- 현실 성인 비율 7.3~7.8등신을 기본으로 하고, 탑뷰 가독성을 위한 머리 확대는 실제 대비 최대 8%로 제한한다.
- 몸통은 방탄판의 사각형이 아니라 흉곽→허리로 좁아지는 실루엣을 유지한다.
- 팔 두께는 소매 포함 상완 0.11~0.15 m, 전완 0.09~0.13 m 범위를 기준으로 한다.
- 총기 없는 기준 캐릭터, 팔·손, 주무기, 보조무기, 장비를 별도 레이어로 제작한다.
- 상체 조준과 하체 이동을 분리한다. 상체 회전 ±110° 이후에는 발 디딤 전환으로 몸 전체가 따라간다.
- 주손은 권총손잡이, 보조손은 총열덮개·수직손잡이의 실제 파지점에 고정한다. 개머리판 기준점은 어깨 관절 바깥 0.03~0.07 m에 둔다.
- 총열 축은 어깨→손이 아니라 **개머리판→약실→총구**의 일직선으로 관리한다. 총구가 몸 중심보다 확실히 전방에 있어야 한다.
- 장총 휴대 자세에서 총몸이 흉곽을 가로질러 박히지 않고, 저준비/고준비/조준의 세 자세를 구분한다.

#### 화면 결과

- 일반 복도에서 캐릭터 어깨는 문 폭 절반 안팎이고, 장총은 전방으로 뻗어 방향을 즉시 읽을 수 있다.
- 좌우 조준 전환 때 팔이 꺾이거나 총이 겨드랑이를 관통하지 않는다.
- 조끼·백팩은 몸의 깊이를 만들지만 충돌 폭이나 선택 원을 키우지 않는다.

#### 검수 기준

- 모든 무기군·8방향·서기/앉기/이동 조합의 손-그립 오차 4 px 이하.
- 개머리판-어깨 간격 2~6 px, 총몸-흉곽 겹침 면적이 총기 면적의 15% 이하.
- 100%/75%/50% 줌 비교에서 실루엣이 인간 비율로 보이고 문·복도 대비 과체중 인상이 없어야 한다.

### 10.2 총기 고증

#### 목표

총기마다 크기·작동·반동·소리·운용 방식이 구별되고, 단순 스탯 스킨처럼 보이지 않게 한다.

#### 구현 기준

- 무기 데이터: 전체 길이, 총열 길이, 탄종, 작동 방식, 발사 속도, 탄창 용량, 장전 방식, 질량, 조준 시간, 반동 패턴, 관통 등급.
- 실제 총기명을 쓰는 경우 제조사 상표·각인·독점 외형의 사용 가능 범위를 별도 검토한다. 기본 제작은 현실 총기군을 참고한 허구 모델을 권장한다.
- 탄은 총구에서 생성하며 발사 순간 탄창 감소, 약실·볼트 작동 시각, 탄피 배출 방향을 무기 데이터에 둔다.
- 반동은 카메라 랜덤 흔들림이 아니라 총구 방향·후속탄 분산·상체 애니메이션으로 표현한다.
- 소음기, 광학 장비, 손잡이는 지정 레일·나사산 소켓에만 부착한다.
- 재장전은 탄창 교환형, 탄환 개별 장전형, 벨트/박스형, 비상/전술 장전을 구분한다.

#### 실패 위험과 검수

- 총기 길이를 캐릭터 크기에 맞춰 임의 축소하지 않는다. 카빈·기관단총·소총·산탄총의 실루엣 길이 순서가 유지되어야 한다.
- 분당 발사 수와 애니메이션·사운드 발사 수가 10초 측정에서 ±1발 이내로 일치한다.
- 탄창 교환 전에 탄약이 채워지거나, 빈 탄창인데 약실탄 없이 즉시 발사되는 오류가 없어야 한다.
- 총구 섬광·탄피·탄도 시작점이 모든 자세에서 총기 소켓과 일치한다.

### 10.3 장비와 가젯

- 설치 장비는 손→표면 접촉→고정→활성의 단계를 가진다. 바닥 장비가 벽 각도로 서거나 공중에 뜨지 않는다.
- 투척 장비는 손 소켓에서 분리되고 포물선·충돌·회전을 사용한다. 캐릭터 중심에서 순간 생성하지 않는다.
- 카메라·센서는 렌즈 방향이 실제 탐지 부채꼴과 일치한다.
- 장비 실루엣은 탑뷰에서도 앞/뒤와 기능 방향을 알 수 있어야 한다.
- 고유 장비는 현실 장비 원리를 참고하되 이름, 실루엣, 효과 조합을 독자적으로 설계한다.

검수: 설치 가능한 표면 20종에서 접촉 오차 0.03 m 이하, 공중 부유·벽 관통 0건. 렌즈·총구·센서 방향과 실제 효과 방향 오차 3° 이하.

### 10.4 복장과 보호장비

- 방탄판은 흉골과 주요 장기를 덮는 높이에, 탄창 파우치는 꺼낼 수 있는 방향으로, 무전기는 케이블과 PTT 위치가 연결되게 배치한다.
- 벨트 장비는 권총, 탄창, 응급키트, 유틸리티가 서로 겹치지 않고 앉기·엎드리기를 방해하지 않게 한다.
- 공격/방어 역할 차이는 색이 아니라 장비 구성으로 드러낸다. 돌파 담당은 도구·폭약, 정보 담당은 센서·단말, 중장갑은 판넬과 헬멧 부피가 증가한다.
- 국적·부대 모티프는 기후, 장비 조달 체계, 착용 방식으로 표현하고 국기·실제 부대 마크는 선택적·허구화한다.
- 여성·남성 체형은 성적 과장 대신 어깨, 골반, 장비 핏의 작은 차이로 표현하며 동일 장비 기능과 히트박스를 유지한다.

검수: 정면·후면·좌우·탑뷰 콘셉트 시트에서 모든 파우치와 도구의 용도·고정 방식이 설명 가능해야 한다. 서로 다른 오퍼레이터 5명의 흑색 실루엣 구분 성공률 80% 이상.

## 11. 애니메이션

### 목표

AI의 의도가 자세 변화로 먼저 읽히고, 발 미끄러짐·손 분리·즉시 방향 반전 없이 무게감 있는 전술 움직임을 만든다.

### 필수 상태

`IDLE_LOW`, `IDLE_AIM`, `WALK`, `TACTICAL_WALK`, `SPRINT`, `CROUCH`, `LEAN`, `ADS`, `FIRE`, `RELOAD_TACTICAL`, `RELOAD_EMPTY`, `THROW`, `DEPLOY`, `MELEE`, `HIT`, `INCAPACITATED`, `REVIVE`, `DEATH`.

### 전환 기준

| 전환 | 권장 시간 | 핵심 조건 |
|---|---:|---|
| 정지→전술 보행 | 100~160 ms | 첫 발이 이동 방향을 선행 |
| 보행→질주 | 180~260 ms | 무기 저준비 전환 포함 |
| 질주→조준 | 260~420 ms | 정지·상체 안정 후 사격 정확도 회복 |
| 좌우 급회전 | 160~280 ms | 하체 피벗 후 상체 정렬 |
| 피격 반응 | 80~180 ms | 사격 입력을 완전히 잠그지 않음 |
| 사망 | 450~900 ms | 피격 방향·운동량 반영, 과장된 비행 금지 |

- 이동 속도와 보폭으로 애니메이션 재생률을 계산해 발 미끄러짐을 억제한다.
- 조준 방향은 16방향 이상 또는 본/벡터 방식으로, 하체 이동은 8방향 이상 지원한다.
- 총기 발사 반동은 손→팔→어깨 순으로 전달되고 80~140 ms에 회복한다.
- 피격 애니메이션은 판정 지연을 만들지 않으며, 짧은 상체 가산 애니메이션으로 처리한다.
- 설치·재장전의 실제 완료 프레임에 `commit` 이벤트를 둔다. 애니메이션 시작과 동시에 결과를 적용하지 않는다.

### 실패하기 쉬운 지점

- 상체와 총기 레이어의 회전 중심이 달라 손이 총에서 떨어짐.
- 이동 벡터가 바뀌는 즉시 스프라이트를 뒤집어 다리가 순간 반전됨.
- 총을 쏠 때 캐릭터 전체를 뒤로 이동시켜 충돌 위치와 화면 위치가 달라짐.

### 검수 기준

- 8방향 이동+16방향 조준 조합 전수에서 손 분리, 팔 역관절, 총기 몸 관통 0건.
- 5초 이동 후 발 기준 누적 미끄러짐이 한 보폭의 10% 이하.
- 재장전·설치 중 취소 가능한 시점 전후의 탄약·장비 상태가 명세와 정확히 일치한다.

## 12. 총격 이펙트·사운드·타격감

### 목표

명중 결과를 과장된 숫자나 화면 흔들림 없이도 즉시 이해하게 하고, 총기·거리·공간·재질의 차이가 한 번의 교전에서 느껴지게 한다.

### 12.1 발사 표현

- 총구 섬광은 40~70 ms, 2~3프레임 변형을 사용하며 밝은 환경·소음기에서는 크기를 줄인다.
- 예광 표현은 모든 탄이 아니라 기본 3~5발 중 1발만 사용한다. 실제 탄도보다 늦거나 곡선으로 휘지 않는다.
- 총기 반동은 총기·상체가 먼저 반응하고 카메라는 교전 줌에서만 1~3 px의 저주파 충격을 허용한다.
- 탄피는 시각 장식이며 판정 충돌을 갖지 않는다. 바닥·벽 접촉음 동시 재생 수를 제한한다.

### 12.2 피격과 재질

| 재질 | 시각 | 소리 | 판정 피드백 |
|---|---|---|---|
| 인체/보호구 | 짧은 방향성 반응, 선택적 혈흔 | 둔탁한 충격+장비 마찰 | 체력·부상 상태, 과한 히트마커 금지 |
| 목재 | 파편, 구멍 확대 | 건조한 파열 | 관통 후 위력 감소 |
| 석고/벽돌 | 분진, 작은 파편 | 중저역 충격 | 탄종별 관통·파괴 |
| 금속 | 섬광성 스파크 소량 | 짧은 고역 충격 | 도탄 가능 |
| 유리 | 균열→파편 | 얇은 파열 | 초기 탄 감쇠 소량 |

- 피격 방향은 짧은 몸 반응과 바닥 파편 방향으로 읽히게 한다.
- 헤드 치명타는 별도 점수 팝업 대신 헬멧 반응, 명확한 사운드 차이, 즉시 생존 카드 전환으로 전달한다.
- 화면 전체 적색 플래시는 방송 화면에 사용하지 않는다.

### 12.3 총기 사운드

한 발은 `기계 작동 + 총구 폭발 + 근거리 충격 + 실내/실외 반사 + 원거리 꼬리 + 탄착` 레이어로 구성한다.

- 총기군마다 발사 속도뿐 아니라 저역 충격, 금속 작동, 꼬리 길이가 달라야 한다.
- 실내는 초기 반사와 짧은 밀도, 실외는 직접음과 긴 원거리 꼬리를 강조한다.
- 소음기는 무음이 아니라 총구 폭발 감소와 기계음·탄착음 상대 강조로 표현한다.
- 동일 샘플 반복을 피하도록 핵심 레이어 4개 이상 변형하고 피치 랜덤은 ±2% 이내로 제한한다.
- 자동사격은 낱발 샘플을 무리하게 겹치지 않고 발사 속도에 맞춘 연속 레이어 또는 동시 발음 제한을 사용한다.

### 화면에서 보여야 할 결과

- 음소거 상태에서도 발사자, 탄도, 피격 재질, 피해 결과를 읽을 수 있다.
- 화면을 보지 않아도 소리만으로 소총·기관단총·산탄총, 실내·실외, 근거리·원거리가 대체로 구분된다.
- 한 교전에서 섬광·연기·분진이 캐릭터와 총구를 0.3초 이상 완전히 가리지 않는다.

### 실패하기 쉬운 지점

- 모든 총에 같은 “전자음·통통 튀는” 샘플을 피치만 바꿔 사용함.
- 탄착 이펙트가 탄보다 먼저 나오거나 총구와 다른 각도로 날아감.
- 명중마다 카메라를 흔들어 방송 시인성과 멀미를 악화함.
- 분진과 연막이 단순 알파 이미지라 시야 판정과 화면이 다름.

### 검수 기준

- 프레임 단위 녹화에서 총구 섬광→탄도/즉시 탄착 판정→피격 반응의 순서가 시뮬레이션 이벤트와 일치한다.
- 총기군 4종 블라인드 청음 테스트에서 5명 중 4명 이상이 75% 이상 구분한다.
- 10명이 자동사격·파괴·연막을 동시에 사용해도 사운드 클리핑 0건, 핵심 발사·피격 이벤트 누락률 5% 이하.

## 13. 목표 장치와 핵심 사건 연출

### 목표

라운드 후반의 승리 조건을 총격보다 우선해 읽히게 하되, 화면을 거대한 경고 UI로 덮지 않는다.

### 구현 기준

- 장치 운반자는 월드 링 내부에 작은 케이스 표식, 로스터 카드에 동일 표식을 표시한다.
- 설치 시작 시 목표 카드, 설치자 포커스, 접근 중인 가장 가까운 적의 방향을 갱신한다.
- 설치·해제 진행률은 연속 바와 숫자 초 중 하나만 사용한다. 둘을 중복 표시하지 않는다.
- 장치 작동음은 남은 시간 구간별로 간격이 짧아지되 정확한 폭발 시각은 권위 타이머가 결정한다.
- 해제 중 행동자가 사망·이동·피격으로 취소되면 1틱 안에 진행 표시가 사라지고 취소 사유를 이벤트 로그에 남긴다.

### 검수 기준

- 장치가 화면 밖이어도 운반·설치·활성·해제 상태를 HUD에서 1초 안에 이해할 수 있다.
- 설치 이후 남은 공격팀이 0명이 되어도 라운드가 조기 종료되지 않는다.
- 시간 종료와 설치 완료가 같은 틱인 자동 테스트에서 명시된 완료 이벤트 우선순위가 적용된다.

## 14. 데이터 정의와 이벤트 계약

### 핵심 데이터

```ts
type MatchEvent = {
  tick: number;
  seq: number;
  type: 'SHOT' | 'HIT' | 'DOWN' | 'KILL' | 'SPOT' | 'SOUND' |
        'GADGET' | 'BREACH' | 'PLANT_START' | 'PLANT_COMPLETE' |
        'DISABLE_START' | 'DISABLE_COMPLETE' | 'ROUND_END';
  actorId?: string;
  targetId?: string;
  position?: Vec3;
  payload: Record<string, number | string | boolean>;
};

type AgentRuntime = {
  playerId: string;
  operatorId: string;
  teamId: string;
  role: TacticalRole;
  life: 'ACTIVE' | 'INCAPACITATED' | 'DEAD';
  health: number;
  position: Vec3;
  bodyYaw: number;
  aimYaw: number;
  weaponId: string;
  ammoInMag: number;
  reserveAmmo: number;
  gadgetCharges: Record<string, number>;

  observerTeamId: string;
  targetId: string;

  uncertaintyRadius: number;

  expiresTick: number;

```

### 계약 규칙

- `(tick, seq)`는 전 경기에서 유일하며 같은 틱 사건의 재생 순서를 보장한다.
- UI는 생명·점수 값을 추측해 선반영하지 않고 Authority 상태 또는 확정 이벤트만 읽는다.
- `KILL`은 마지막 피해의 별칭이 아니라 판정 완료 이벤트다. 가해자, 피해자, 무기, 부위, 관통, 지원자를 기록한다.
- 카메라 디렉터는 이벤트를 소비할 수 있지만 새 경기 이벤트를 생성하지 않는다.
- 데이터 ID와 표시 이름을 분리해 선수 이적·닉네임 변경·현지화가 리플레이를 깨지 않게 한다.

## 15. 라운드 종료·리플레이·분석

### 목표

결과를 보여주는 데서 끝나지 않고 승패 원인을 감독이 다음 의사결정에 사용할 수 있게 한다.

### 구성

1. 0~1.2초: 승리 팀, 승리 사유, 최종 인원 표시.
2. 1.2~5.5초: 핵심 장면 1개 재생. 첫 진입킬보다 승률 변화가 가장 큰 사건을 우선한다.
3. 5.5~7초: 다음 라운드로 연결되는 핵심 지표 3개 표시.

핵심 지표 예시: 첫 교전, 교환 성공, 설치까지 걸린 시간, 장비 잔존, 미확인 구역 진입, 수적 우세 전환, 선수별 영향도. 단일 “평점”만 보여주지 말고 관찰 가능한 원인과 연결한다.

### 검수 기준

- 리플레이의 탄약, 파괴 상태, 생존 상태, 장치 상태가 원본과 100% 일치한다.
- 핵심 장면은 승률 변화량 1위 사건 또는 목표 완료 사건을 90% 이상 선택한다.
- 결과 화면의 모든 수치는 이벤트 로그 재집계 값과 일치한다.

## 18. 구현 우선순위

### 1단계 — 판정 가능한 회색 상자

한 층, 한 목표 구역, 10개 캡슐, 이동·LOS·사격·피해·사망·타이머·승패·결정론 로그를 구현한다. 임시 그래픽이어도 P0-01~04가 먼저 통과해야 한다.

### 2단계 — 전술과 정보

Team Knowledge, 소리 추정, 역할 AI, 설치·해제, 파괴 3단계를 추가한다. 전지적 좌표 누출 테스트를 자동화한다.

### 3단계 — 방송 수직 슬라이스

Strategic Wide, Contact, Objective, Clutch 카메라와 핵심 HUD를 구현한다. 한 라운드를 처음부터 끝까지 손대지 않고 관전해도 이해 가능해야 한다.

### 4단계 — 캐릭터·총기 완성

기준 캐릭터 1명, 무기군 4종, 장비 4종으로 비율·소켓·애니메이션·사운드 품질 기준을 확정한 뒤 전체 오퍼레이터에 확장한다. 개별 캐릭터를 먼저 대량 제작하지 않는다.

### 5단계 — 리플레이와 감독 분석

핵심 장면 선택, 라운드 원인 지표, 선수 시즌 데이터 연결을 구현한다. 이 단계부터 경기 결과가 구단 운영 의사결정으로 환류한다.

## 부록 A. 아트 납품 단위

각 오퍼레이터는 아래 묶음이 모두 있어야 구현팀에 전달할 수 있다.

1. 총기·가젯을 결합하지 않은 기준 캐릭터: 정면, 후면, 좌우, 3/4, 탑뷰.
2. 머리·몸통·팔·손·다리·백팩의 분리 레이어와 회전 중심.
3. 저준비·고준비·조준 자세의 손/어깨 소켓 좌표.
4. 주무기·보조무기·투척·설치 장비의 독립 스프라이트와 앞/뒤 방향.
5. 팀색 마스크, 재질 마스크, 피격·사망 변형.
6. 100%/75%/50% 줌 시트와 표준 문·복도 위 스케일 비교.
7. 실제 장비 모티프, 허구화한 요소, 사용 금지 표식이 적힌 고증 메모.

## 부록 B. 한 라운드 수동 검수 순서

1. 준비 단계에서 방어 설치와 공격 정찰이 교전 없이 진행되는지 본다.
2. 전략 줌에서 10명의 팀·선수·오퍼레이터·시선 방향을 구분한다.
3. 첫 접촉 전에 카메라가 양측과 엄폐를 화면에 잡는지 본다.
4. 총구, 탄도, 탄착, 피격, 킬 피드 순서를 프레임 단위로 확인한다.
5. 미발견 적을 AI와 팀 UI가 추적하지 않는지 디버그 지식층과 비교한다.
6. 설치 후 공격 전멸, 해제 중 피격, 제한 시각 도달을 각각 재현한다.
7. 리플레이와 원본의 탄약·파괴·인원·장치 상태를 비교한다.
8. 1366×768, 색각 필터, 모션 감소 설정에서 같은 라운드를 다시 확인한다.

이 명세의 우선순위는 항상 **판정 정확성 → 정보 정직성 → 전술 가독성 → 고증 → 연출 강도** 순서다. 더 화려한 연출이 앞 단계의 기준을 훼손하면 연출을 줄인다.
